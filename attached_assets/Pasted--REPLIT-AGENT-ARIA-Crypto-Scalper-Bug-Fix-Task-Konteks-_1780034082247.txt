# REPLIT AGENT — ARIA Crypto Scalper: Bug Fix Task

## Konteks
Ini adalah Rust codebase untuk autonomous crypto scalper bot bernama ARIA.
Kerjakan semua fix di bawah **satu per satu secara berurutan**, pastikan tidak ada
compile error setelah setiap perubahan. Jangan mengubah logika trading, hanya fix
bug yang disebutkan.

## FIX 1 — `src/agents/brain.rs` — Hapus Override NoGo → Go

### Masalah
Block berikut secara salah membalik keputusan LLM: jika LLM 70% yakin trade adalah
buruk (NoGo confidence 70), sistem paksa jadi GO. Selain itu log message menyebut
">=55" padahal kode cek `>= 50`.

### Lokasi
Cari block ini (sekitar baris 240–253):
```rust
// OVERRIDE: if LLM says NoGo but confidence >= 50, force Go
// (LLM reasoning models sometimes misclassify despite good signals)
let mut final_decision = llm_out.decision.clone();
if final_decision.decision == Decision::NoGo
    && final_decision.confidence >= 50
{
    info!(
        symbol = %symbol,
        confidence = final_decision.confidence,
        "brain: OVERRIDE — LLM said NoGo but confidence >= 55, forcing Go"
    );
    final_decision.decision = Decision::Go;
}
```

### Fix
Ganti seluruh block override itu dengan hanya:
```rust
let final_decision = llm_out.decision.clone();
```

Hapus 10 baris override tersebut. `final_decision` tetap dipakai oleh kode setelahnya
(`if final_decision.decision != Decision::Go { ... }`), jadi tidak perlu tambahan kode.

## FIX 2 — `src/agents/survival.rs` — Perbaiki Ratchet Logic (Selalu False)

### Masalah
Kondisi `snap.realized_pnl_today < lock_floor` di mana `lock_floor = realized_pnl_today * 0.5`
**tidak pernah true** untuk nilai positif (x tidak pernah < x/2). Fitur ratchet mati total.

### Lokasi
Cari block ini (sekitar baris 421–431):
```rust
let mut ratchet_locked = false;
if realized_pct >= cfg.daily_pnl_ratchet_pct {
    let lock_floor = snap.realized_pnl_today * 0.5;
    if snap.realized_pnl_today < lock_floor {
        ratchet_locked = true;
        reasons.push(format!(
            "ratchet locked: daily PnL ${:.2} < lock ${:.2}",
            snap.realized_pnl_today, lock_floor
        ));
    }
}
```

### Fix
Ganti dengan logika yang benar — bandingkan equity saat ini terhadap peak dikurangi
setengah profit:
```rust
let mut ratchet_locked = false;
if realized_pct >= cfg.daily_pnl_ratchet_pct && g.daily_pnl > 0.0 {
    // Protect 50% of today's profit: if equity has given back more than half
    // the day's gain, engage ratchet (reduce to Defensive mode).
    let protected_amount = g.daily_pnl * 0.5;
    let equity_floor = g.daily_peak_equity - protected_amount;
    if snap.equity < equity_floor {
        ratchet_locked = true;
        reasons.push(format!(
            "ratchet: equity ${:.2} < floor ${:.2} (protecting 50% of ${:.2} daily gain)",
            snap.equity, equity_floor, g.daily_pnl
        ));
    }
}
```

## FIX 3 — `src/agents/survival.rs` — Perbaiki `apply_state()` Frozen Arm

### Masalah
Arm `SurvivalMode::Frozen` di `apply_state()` memanggil `risk.unfreeze()`, yang justru
membuka kunci bot ketika seharusnya frozen. Juga `recompute()` tidak pernah return
`Frozen` (hanya return Healthy/Cautious/Defensive/Dead), menjadikan arm ini dead code
yang berbahaya.

### Lokasi — bagian 1
Cari di `apply_state()` (sekitar baris 503–514):
```rust
SurvivalMode::Frozen => {
    // Frozen mode should NOT exist in normal operation anymore.
    // If somehow entered, treat as Defensive (reduce size, don't freeze).
    risk.set_size_multiplier(0.3);
    if risk.is_frozen() {
        // Only unfreeze if it was a survival auto-freeze, not manual
        risk.unfreeze();
    }
}
```

### Fix — bagian 1
Ganti dengan arm yang benar:
```rust
SurvivalMode::Frozen => {
    // Full stop — no new positions allowed.
    risk.set_size_multiplier(0.0);
    risk.freeze("survival: Frozen mode active".into());
}
```

### Lokasi — bagian 2 (broken test)
Cari di bagian `#[cfg(test)]` di bawah file yang sama (sekitar baris 596–610):
```rust
#[test]
fn cooldown_forces_frozen_mode() {
    ...
    assert!(matches!(s.mode, SurvivalMode::Frozen));
}
```

### Fix — bagian 2
Ganti nama test dan assertion karena `recompute()` memang tidak return `Frozen`
saat cooldown — return `Defensive`. Update test menjadi:
```rust
#[test]
fn cooldown_forces_defensive_mode() {
    let cfg = cfg();
    let inner = inner();
    on_position_closed(&inner, -10.0, &cfg);
    on_position_closed(&inner, -10.0, &cfg);
    on_position_closed(&inner, -10.0, &cfg);
    let risk = Arc::new(RiskManager::new(limits(), 1000.0));
    risk.on_position_closed(-30.0);
    let s = recompute(&inner, &risk, &cfg, 1000.0);
    // Cooldown active → Defensive (not Frozen — Frozen only via apply_state manually)
    assert!(matches!(s.mode, SurvivalMode::Defensive | SurvivalMode::Cautious));
    assert!(s.size_multiplier <= 0.6);
}
```

## FIX 4 — `src/learning/policy.rs` — Perbaiki Test yang Broken

### Masalah
Test `lose_streak_blocks` mengassert `!v.allowed`, tapi fungsi `evaluate()` setelah
refactor tidak pernah meng-set `verdict.allowed = false` (kode lama menggunakan
`is_block()` yang sudah dihapus). Test akan selalu gagal.

### Lokasi
Cari test `lose_streak_blocks` (sekitar baris 200–220):
```rust
#[test]
fn lose_streak_blocks() {
    ...
    let v = policy.evaluate("ema_ribbon", "TRENDING", "BTCUSDT");
    assert!(!v.allowed);        // ← INI SELALU FAIL
    assert_eq!(v.size_multiplier, 0.0);  // ← INI JUGA FAIL (min 0.5 sekarang)
    assert!(!v.matched_lessons.is_empty());
    ...
}
```

### Fix
Update assertions sesuai perilaku policy yang baru (reduce size, never block):
```rust
#[test]
fn lose_streak_reduces_size() {
    // 3 consecutive losses on same (strategy, symbol) triggers LoseStreak.
    let trades = vec![
        t("ema_ribbon", "BTCUSDT", "TRENDING", -1.0),
        t("ema_ribbon", "BTCUSDT", "TRENDING", -1.0),
        t("ema_ribbon", "BTCUSDT", "TRENDING", -1.0),
    ];
    let mem = PerformanceMemory::build(&trades);
    let extractor = LessonExtractor::new(LessonConfig::default());
    let lessons = extractor.extract(&mem);
    let policy = LearningPolicy::default();
    policy.update(mem, lessons);

    let v = policy.evaluate("ema_ribbon", "TRENDING", "BTCUSDT");
    // Policy no longer blocks, only reduces size (min 0.5 enforced)
    assert!(v.allowed);
    assert!(v.size_multiplier < 1.0);   // size dikurangi
    assert!(v.size_multiplier >= 0.5);  // tapi tidak pernah di bawah minimum
    assert!(!v.matched_lessons.is_empty());

    // Different symbol still at full size.
    let v2 = policy.evaluate("ema_ribbon", "TRENDING", "ETHUSDT");
    assert!(v2.allowed);
    assert!((v2.size_multiplier - 1.0).abs() < 0.01); // no lesson matched
}
```

## FIX 5 — `src/agents/execution.rs` — Ganti DefaultHasher dengan Hasher Deterministik

### Masalah
`std::collections::hash_map::DefaultHasher` menggunakan random seed per-process
sejak Rust 1.36. Setiap restart bot menghasilkan hash berbeda untuk input sama,
sehingga client_id tidak benar-benar idempotent antar restart. Bot yang crash dan
restart bisa membuka posisi duplikat.

### Langkah 1 — Tambah dependency ke `Cargo.toml`
Buka `Cargo.toml`, cari blok `[dependencies]`, tambahkan:
```toml
rustc-hash = "1.1"
```

### Langkah 2 — Update `src/agents/execution.rs`
Cari fungsi `idempotent_client_id` (sekitar baris 710–737):
```rust
fn idempotent_client_id(
    symbol: &str,
    strategy: &str,
    side: &Side,
    entry: f64,
    size: f64,
) -> String {
    use std::collections::hash_map::DefaultHasher;
    use std::hash::{Hash, Hasher};
    let bucket = Utc::now().timestamp() / 60; // 1-minute bucket
    let side = match side {
        Side::Long => "L",
        Side::Short => "S",
    };
    let mut h = DefaultHasher::new();
    (
        symbol,
        strategy,
        side,
        (entry * 1e6) as i64,
        (size * 1e6) as i64,
        bucket,
    )
        .hash(&mut h);
    format!("aria-{}-{}-{:x}", symbol, side, h.finish())
}
```

Ganti dengan:
```rust
fn idempotent_client_id(
    symbol: &str,
    strategy: &str,
    side: &Side,
    entry: f64,
    size: f64,
) -> String {
    use rustc_hash::FxHasher;
    use std::hash::{Hash, Hasher};
    let bucket = Utc::now().timestamp() / 60; // 1-minute bucket
    let side_str = match side {
        Side::Long => "L",
        Side::Short => "S",
    };
    // FxHasher is deterministic across processes (no random seed).
    let mut h = FxHasher::default();
    (
        symbol,
        strategy,
        side_str,
        (entry * 1e6) as i64,
        (size * 1e6) as i64,
        bucket,
    )
        .hash(&mut h);
    // Binance newClientOrderId max 36 chars, alphanumeric + hyphen only
    format!("aria-{}-{}-{:x}", symbol, side_str, h.finish())
        .chars()
        .take(36)
        .collect()
}
```

Tambahkan import di atas file jika belum ada:
```rust
use rustc_hash::FxHasher;
```
(atau biarkan di dalam fungsi saja, keduanya valid)

## FIX 7 — `src/agents/brain.rs` — Validasi SL/TP Setelah LLM Adjustment

### Masalah
LLM bisa mengubah SL/TP ke level yang salah (SL di atas entry untuk Long, TP di
bawah entry, atau R:R buruk). Perubahan ini terjadi setelah `risk.validate_signal()`
dipanggil, sehingga bypass semua risk gate.

### Lokasi
Cari (sekitar baris 160–175):
```rust
let final_sl = llm_out.decision.sl_adjustment.unwrap_or(signal.stop_loss);
let final_tp = llm_out.decision.tp_adjustment.unwrap_or(signal.take_profit);
let final_entry = llm_out.decision.entry_price.unwrap_or(signal.entry);
```

### Fix
Tambahkan validasi geometri setelah baris tersebut:
```rust
let raw_sl = llm_out.decision.sl_adjustment.unwrap_or(signal.stop_loss);
let raw_tp = llm_out.decision.tp_adjustment.unwrap_or(signal.take_profit);
let final_entry = llm_out.decision.entry_price.unwrap_or(signal.entry);

// Validate LLM-adjusted SL/TP geometry — reject if wrong side of entry
let geometry_ok = match signal.side {
    crate::data::Side::Long => raw_sl < final_entry && raw_tp > final_entry,
    crate::data::Side::Short => raw_sl > final_entry && raw_tp < final_entry,
};
if !geometry_ok {
    info!(
        symbol = %symbol,
        sl = raw_sl, tp = raw_tp, entry = final_entry,
        side = %signal.side.as_str(),
        "brain: REJECTED — LLM-adjusted SL/TP geometry invalid"
    );
    continue;
}

// Validate minimum R:R after LLM adjustment
let risk_dist = (final_entry - raw_sl).abs();
let reward_dist = (raw_tp - final_entry).abs();
let rr = if risk_dist > 0.0 { reward_dist / risk_dist } else { 0.0 };
if rr < 0.8 {
    info!(
        symbol = %symbol,
        rr = %format!("{:.2}", rr),
        "brain: REJECTED — LLM-adjusted SL/TP gives R:R < 0.8"
    );
    continue;
}

let final_sl = raw_sl;
let final_tp = raw_tp;
```
